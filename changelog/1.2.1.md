# Version 1.2.1 release

Commit range: `edf2e20..86750c1`

## Highlights
- **Free mode for local documents**: `kodama build --free`, `check --free`, and `serve --free` work in the current directory without a configuration file, with build output written beside the sources.
- [Experimental] **Compile-time Markdown math rendering**: opt in with `[build].pre-render-math = true` to render formulas to HTML using tonic instead of relying on browser-side rendering.
- **Nested Typst sections work out of the box**: the built-in template, authoring documentation, and featured demo now import `"/_lib/kodama.typ"`, resolving the library from Typst's configured root rather than the article's directory ([#118](https://github.com/kodama-community/kodama/issues/118)).

## Free mode
- Recursively discovers Markdown and Typst sections, including `README.md`, and writes adjacent `.html` files. Typst library/resource files use the existing SVG compilation path.
- Uses resources in place without copying assets. Section links become relative HTML URLs, and embedded resources retain their source-relative meaning.
- Inlines built-in CSS and JavaScript, skips workspace `import-*.html` files and the fixed favicon, and keeps caches in `.cache`.
- Disables RSS and defaults to no metadata or graph indexes; `--indexes` and `--graph` can explicitly enable the latter outputs.
- Watches sources and recorded dependencies for recompilation; ordinary resource changes trigger browser reload. Generated files, temporary files, and caches are ignored.
- The built-in preview server rejects hidden paths and symlinks escaping the workspace.

## Markdown math and diagnostics
- Added `[build].pre-render-math`, disabled by default. Compile-time rendering uses independent macro state for each formula and reports rendering errors with the section slug.
- Browser-side math rendering now targets explicit formula elements instead of scanning the entire document body, avoiding accidental rendering of ordinary text containing delimiters.
- Parsing now carries diagnostics through Markdown, subtrees, and inline Typst batches instead of relying on global error flags.
- Ordinary builds retain rendered math/include error content, while `kodama check` treats these diagnostics as errors. Fatal rendering failures still stop builds.

## Fixes and internal improvements
- Configuration loading reads exactly the requested file and reports a missing file instead of searching parent directories.
- Theme paths remain explicitly watched, including HTML theme files otherwise excluded from ordinary HTML change events.
- Reorganized compiler, Markdown, HTML, and Typst modules and consolidated shared integration-test helpers.
- Vendored tonic for compile-time math rendering.
- Updated the parsed-content cache schema and separated Free-mode cache identity from configured-site mode.

## Behavior changes and migration notes
- Commands requiring configuration no longer fall back to a parent directory. Run from the site root or pass an explicit path such as `-c ../Kodama.toml`.
- `--free` conflicts with `--config` and ignores an existing `Kodama.toml`. It is an in-place workflow, not an isolated publish directory: existing adjacent output files can be overwritten, resources are not copied, and generated files are not removed when sources are deleted.
- Existing Typst articles and custom templates are not rewritten. With the default Typst root of `trees/`, replace `#import "_lib/kodama.typ": *` with `#import "/_lib/kodama.typ": *` to support nested articles. A custom Typst root must expose the library at the corresponding `/_lib/kodama.typ` path.
- Compile-time math rendering is opt-in. Invalid formulas produce visible error content and diagnostics rather than falling back to browser rendering.
